# Justificación del Proyecto – Dead Harvest

## Proyecto

**Dead Harvest** es un videojuego 2D de acción y supervivencia con perspectiva cenital, en el que el jugador debe sobrevivir a diferentes oleadas de zombis utilizando armas cuerpo a cuerpo. El juego combina combate, movimiento, estrategia, administración de recursos y progresión de dificultad.

## 1. ¿Qué problema busca resolver el videojuego?

Dead Harvest busca ofrecer una experiencia de entretenimiento basada en partidas rápidas, desafiantes y dinámicas, donde el jugador deba tomar decisiones constantemente para sobrevivir.

El proyecto busca resolver la necesidad de contar con una experiencia de juego sencilla de comprender, pero que mantenga un nivel de desafío progresivo. Para lograrlo, el videojuego utiliza mecánicas de movimiento, esquiva, combate cuerpo a cuerpo, administración de estamina, enfrentamiento contra diferentes tipos de enemigos y mejoras entre oleadas.

De esta manera, el jugador no solamente debe reaccionar ante los enemigos, sino también administrar sus recursos y decidir cuándo atacar, esquivar o aprovechar las mejoras disponibles.

## 2. ¿Por qué el proyecto resulta relevante?

El proyecto resulta relevante porque permite desarrollar un videojuego que combina diferentes elementos de programación y diseño dentro de un mismo sistema.

Dead Harvest está diseñado alrededor de partidas basadas en oleadas, lo que permite mantener una dificultad progresiva y generar una experiencia de juego dinámica. La utilización exclusiva de armas cuerpo a cuerpo también permite que el jugador tenga que acercarse a los enemigos y tomar decisiones sobre el momento adecuado para atacar o retirarse.

Además, el proyecto permite aplicar conceptos de diseño de videojuegos como interacción jugador-sistema, inteligencia artificial de enemigos, interfaz de usuario, progresión, administración de recursos y diseño de niveles.

## 3. ¿Qué aporta la Ingeniería de Software al desarrollo del proyecto?

La Ingeniería de Software permite organizar y controlar el desarrollo de Dead Harvest mediante procesos, técnicas y herramientas que facilitan el trabajo del equipo.

El uso de la metodología **Scrum** permite dividir el desarrollo en actividades y entregas pequeñas mediante Sprints, facilitando la planificación, asignación de responsabilidades y seguimiento del progreso.

Además, herramientas como la **Especificación de Requisitos de Software (ERS)**, historias de usuario, casos de uso, diagramas UML y Product Backlog permiten definir claramente las funcionalidades que debe tener el videojuego antes de implementarlas.

Esto ayuda a reducir errores, evitar inconsistencias entre los integrantes del equipo y mantener una relación clara entre los requisitos y las funcionalidades que posteriormente serán desarrolladas.

## 4. Importancia técnica del proyecto

Desde el punto de vista técnico, Dead Harvest permite integrar diferentes componentes de un videojuego dentro de un sistema estructurado.

Entre los principales elementos que se desarrollarán se encuentran:

- Sistema de movimiento y control del jugador.
- Sistema de combate cuerpo a cuerpo.
- Sistema de daño y vida.
- Sistema de estamina.
- Diferentes tipos de enemigos.
- Inteligencia artificial mediante estados y comportamientos.
- Sistema de oleadas.
- Sistema de mejoras y progresión.
- Interfaz HUD.
- Menú principal.
- Pantalla de resultados.
- Interacción entre el jugador y los diferentes elementos del sistema.

La integración de estos componentes requiere establecer correctamente las relaciones entre los objetos y sistemas involucrados. Por esta razón, el análisis, diseño y documentación realizados mediante Ingeniería de Software son importantes para mantener una arquitectura organizada y facilitar futuras modificaciones.

## 5. Importancia académica del proyecto

Desde el punto de vista académico, Dead Harvest representa una oportunidad para aplicar de manera práctica los conocimientos adquiridos durante el curso de Ingeniería de Software.

El desarrollo del videojuego permite trabajar con conceptos como requisitos funcionales y no funcionales, historias de usuario, casos de uso, diagramas UML, metodología Scrum, Product Backlog, documentación técnica y control del desarrollo mediante GitHub.

El proyecto también permite comprender la importancia de planificar y documentar un sistema antes y durante su implementación. Cada integrante del equipo asume responsabilidades específicas, lo que permite experimentar un proceso de desarrollo similar al utilizado en proyectos reales de software.

## 6. Conclusión

Dead Harvest es un proyecto que combina entretenimiento y aplicación práctica de conceptos de Ingeniería de Software. Su desarrollo permite construir una experiencia de supervivencia basada en oleadas de zombis, mientras el equipo aplica procesos de análisis, diseño, documentación, desarrollo y control del proyecto.

La utilización de Scrum y de herramientas de modelado y documentación permite organizar el trabajo del equipo y mantener una visión común del sistema. Por ello, el proyecto no solamente busca obtener un videojuego funcional, sino también demostrar la importancia de utilizar una metodología estructurada para desarrollar software de manera organizada, comprensible y mantenible.
